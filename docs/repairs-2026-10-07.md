## 剩余事项

1. **后端开发依赖漏洞**：完整 npm audit 仍报告 20 条中危包级记录，来源为 `sprintf-js` 经参数解析、覆盖率和 Jest 工具链传入。这不是 20 个独立漏洞。生产依赖扫描为 0；没有执行会变更测试工具主要版本的 `npm audit fix --force`，仍需后续升级兼容工具链。
2. **历史凭据轮换**：当前源码清除密码不能撤销 Git 历史或旧文件中出现过的凭据。Neo4j 密码需要在数据库中轮换，再同步各环境连接配置。本次没有修改运行中的数据库密码。
3. **同步持久性边界**：Redis 可用时任务保存在 Redis；Redis 不可用期间任务先留在进程内存，进程在重试成功前退出可能丢失这些任务。已有 Milvus 历史孤立行也没有进行全量清理，必要时需要重建索引。
4. **前端加载体积**：图谱及 UI 库构建分块偏大，仍可继续按需加载和拆包。
5. **验证边界**：没有进行真实付费 LLM / embedding 调用、浏览器完整交互验证、生产模型内容质量评估或线上流量测试。

## 使修复生效

源码修复和本机测试已经完成。运行中的 Kubernetes 服务尚未发布这些改动；本机镜像不会自动替换集群 Deployment。重新发布时需使用包含本次源码的镜像，遵循项目现有部署流程。

本机开发复用 Kubernetes MongoDB / Redis 时，需保持 README 中的两个 `kubectl port-forward` 终端运行，再启动后端与前端。本次诊断创建的临时转发进程会清理，现有 Kubernetes 服务和 Neo4j Desktop 保持原状态。

本机 JWT 密钥已经更换，重启使用新配置的后端后需要重新登录。普通用户自选“医生”身份不会获得图谱管理权限；已有管理员需在业务库中为可信维护人员分配 `doctor` 或 `admin` 角色。
