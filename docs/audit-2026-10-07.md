## 优先处理的问题

### 1. P1：普通用户可以读取全站问答历史【HTTP 隔离复现】

- 位置：[history.controller.ts](D:/MediBrain-Hospital/apps/server/src/history/history.controller.ts:27)。
- `/api/history?all=true` 只验证登录，没有验证管理员角色，就调用 `listAll()`。
- 普通用户测试 token 收到 HTTP 200，并拿到其他用户的模拟问答记录。前端隐藏管理开关不能约束直接请求接口。
- 影响：其他用户问题、回答、身份与用户名泄露。
- 修复：后端在 `all=true` 分支校验管理员权限；覆盖普通用户拒绝、管理员允许和默认仅查询本人三种场景。

### 2. P1：语音文件接口允许越过音频目录读取文件【HTTP 隔离复现】

- 位置：[tts.service.ts](D:/MediBrain-Hospital/apps/server/src/tts/tts.service.ts:64)、[tts.controller.ts](D:/MediBrain-Hospital/apps/server/src/tts/tts.controller.ts:50)。
- `getAudioStream()` 将用户输入直接交给 `join(audioDir, filename)`，没有验证文件名或解析后的路径边界。
- 登录用户请求 `/api/tts/audio/..%2Faudit-marker.txt`，成功得到 HTTP 200 和音频目录外的测试标记文件。本次只读取自己创建的临时文件。
- 影响：攻击者可能读取运行进程有权限访问的配置或其他文件；返回 `audio/mpeg` 不限制内容本身。
- 修复：仅接受服务生成的固定格式文件名，例如 32 位十六进制摘要加 `.mp3`；同时验证解析后的绝对路径处于音频目录内。

### 3. P1：自选医生身份即可取得图谱管理权限【HTTP 隔离复现】

- 位置：[auth.service.ts](D:/MediBrain-Hospital/apps/server/src/auth/auth.service.ts:30)、[graph.guard.ts](D:/MediBrain-Hospital/apps/server/src/graph/guards/graph.guard.ts:16)。
- 注册允许自行提交 `identity=医生`；服务将该值写入 JWT。`GraphGuard` 根据该身份直接授权。
- 注册产生 `role=user` 的 token，随后访问受同一守卫保护的 `/api/graph/meta` 获得 HTTP 200。创建、更新和删除图谱接口共用此守卫；测试没有执行真实写操作。
- 影响：任何注册用户均可通过选择身份获得维护医学知识的权限。
- 修复：回答风格使用的身份与管理授权分开；由管理员授予的可信角色或审核状态决定写权限。

### 4. P1：公开的临时接口可以匿名调用模型【HTTP 隔离复现】

- 位置：[app.controller.ts](D:/MediBrain-Hospital/apps/server/src/app.controller.ts:18)。
- `/api/chat-test` 未配置认证、限流或 DTO 验证。匿名 POST 返回 HTTP 201 并触发模拟模型调用。
- 影响：配置真实模型后，外部请求可以消耗调用额度；该接口还绕开正常问答中的知识检索流程。
- 修复：删除临时接口，或限制为管理员调试接口并增加限流及输入验证。

### 5. P1：否定饮食问题被识别成推荐饮食【服务隔离复现】

- 位置：[entity-recognition.service.ts](D:/MediBrain-Hospital/apps/server/src/entity/entity-recognition.service.ts:17)。
- 输入“高血压不能吃什么”，实际输出维度为 `宜吃食物`，预期为 `忌吃食物`。
- 原因：肯定饮食规则先匹配“吃什么”或“能吃”，覆盖了后面的否定规则。问答服务据此筛选关系，检索方向发生反转。
- 修复：先识别否定语义，并覆盖“不能吃什么”“不宜吃什么”“可以吃什么”等成对场景；也检查同时出现多个意图时的规则。

### 6. P1：版本库脚本包含数据库密码字面量，JWT 还有公开默认值【静态确认】

- 位置：[index-graph.js](D:/MediBrain-Hospital/scripts/embedding/index-graph.js:16)；`scripts/graph-migration/export.js`、`scripts/graph-migration/import4.js`、`scripts/graph-expansion/import.js` 也存在密码回退字面量。
- 这些脚本处于版本控制范围。报告没有复制其中的密码；无法仅凭代码判断这些凭据当前是否仍有效。
- [configuration.ts](D:/MediBrain-Hospital/apps/server/src/config/configuration.ts:6) 和 JWT strategy 允许回退到公开默认密钥。生产环境漏配时可能导致 token 可伪造；本次没有判断现有 `.env` 中的密钥是否安全。
- 修复：密码只从环境变量或密钥服务读取，缺失即报错；移除字面量，并检查是否需要轮换历史中暴露过的实际凭据。生产模式拒绝默认 JWT 密钥。

### 7. P1：禁用账号后，已发出的 token 仍可使用【HTTP 隔离复现】

- 位置：[jwt.strategy.ts](D:/MediBrain-Hospital/apps/server/src/auth/jwt.strategy.ts:23)。
- `validate()` 直接信任 JWT 内的身份和角色，不查询用户当前状态。
- 测试注册后将模拟用户 `isActive` 设为 `false`，原 token 仍可访问图谱接口并获得 HTTP 200。
- 影响：账号禁用或角色撤销不影响既有 token，在其有效期内权限仍然存在。
- 修复：验证当前账号状态；角色变更、禁用与 token 撤销策略一并设计，可通过版本号或受控缓存避免每次完整查询。

## 功能与可靠性问题

### 8. P2：示例环境与 README 的本机启动方式不一致【静态确认】

- 位置：[.env.example](D:/MediBrain-Hospital/.env.example:8)、[docker-compose.yml](D:/MediBrain-Hospital/deploy/docker/docker-compose.yml:41)。
- README 让用户在本机启动 Node 服务，但示例配置使用 Docker 网络名称 `mongo`、`redis`、`neo4j`。这些名称通常只能在对应容器网络内解析。
- Neo4j 的宿主机映射是 7688，代码默认地址却是 `localhost:7687`；MinIO 映射是 9100，示例仍使用容器内 9000。
- 修复：提供与文档一致的本机开发配置和容器部署配置，明确各自的主机名、端口和环境文件优先级。

### 9. P2：识别出的药品等非疾病实体不会直接查邻居【服务隔离复现】

- 位置：[qa.service.ts](D:/MediBrain-Hospital/apps/server/src/qa/qa.service.ts:64)。
- 规则识别阶段对所有类型都调用 `getDiseaseInfo()`。药品、检查、食物等只在向量候选阶段才可能查邻居。
- 测试中已识别“布洛芬”为药品，并提供可用的模拟邻居；向量服务返回空数组时，邻居函数完全未被调用，最终 `graphMatched=false`。
- 修复：按实体类型选择疾病信息或邻居查询；在直接识别成功的情况下使用对应图谱事实。

### 10. P2：Neo4j 出错不会进入现有问答降级【服务隔离复现】

- 位置：[qa.service.ts](D:/MediBrain-Hospital/apps/server/src/qa/qa.service.ts:65)。
- 当前 `try/catch` 只包住 LLM 调用。实体对应的 Neo4j 查询失败时，`ask()` 直接抛错，尚未走到回答降级。
- 测试模拟 `getDiseaseInfo()` 失败，错误从 `ask()` 原样抛出。
- 修复：为图谱、向量、模型分别定义故障结果，返回明确的服务不可用或证据不足状态；保留故障日志。

### 11. P2：切换百炼仍读取 DeepSeek 的 key 与地址【配置隔离复现】

- 位置：[configuration.ts](D:/MediBrain-Hospital/apps/server/src/config/configuration.ts:16)。
- `LLM_PROVIDER=bailian` 时，配置工厂仍读取 `DEEPSEEK_API_KEY`，默认地址也来自 DeepSeek。示例中的 `BAILIAN_API_KEY` 和 `BAILIAN_BASE_URL` 没有被引用。
- 使用合成环境变量复现：provider 显示 bailian，实际选择的是合成 DeepSeek key 和地址。
- 修复：根据 provider 选择对应 key、地址及合理模型默认值，同时保留通用地址显式覆盖能力。

### 12. P2：Milvus 的 5 秒超时计时器没有作用于请求【服务隔离复现】

- 位置：[embedding.service.ts](D:/MediBrain-Hospital/apps/server/src/embedding/embedding.service.ts:144)。
- 创建的 `AbortController` 未接入 SDK 请求，`search()` 参数也未设置 SDK 支持的 `timeout`。
- 模拟请求耗时超过 5.2 秒仍正常等待完成，确认这里声明的 5 秒期限未生效。实际等待上限取决于 SDK 自身配置。
- 修复：配置 SDK 请求超时，并验证超时后的降级与资源释放。

### 13. P2：“查看全部历史”开关被重复反转【前端逻辑复现】

- 位置：[History.vue](D:/MediBrain-Hospital/apps/web/src/views/History.vue:63)。
- `v-model="viewAll"` 已经修改状态；`@change="toggleView"` 又执行 `viewAll.value = !viewAll.value`，抵消切换。
- 按现有绑定与处理函数模拟一次打开操作，最终仍为 `false`。本次未通过实际浏览器点击验证。
- 修复：change 事件只重置分页、重新加载数据，直接使用已经更新的状态。

### 14. P2：分页范围缺少约束，非法记录 ID 变成服务错误【HTTP / 服务隔离复现】

- 位置：[graph.dto.ts](D:/MediBrain-Hospital/apps/server/src/graph/dto/graph.dto.ts:96)、[history.service.ts](D:/MediBrain-Hospital/apps/server/src/history/history.service.ts:70)。
- 图谱查询接受 `page=-2&pageSize=1000000` 并交给服务；DTO 只有转换，没有整数、最小值和最大值验证。历史接口也只有整数转换，没有范围限制。
- `remove('invalid-id', ...)` 抛出 `BSONError`，不是可返回 400 的参数异常。接口默认处理会将此类异常变成 500。
- 修复：分页限制为正整数并设置合理上限；在构造 `ObjectId` 前验证格式。

### 15. P2：图谱管理不会同步更新实体词典或向量索引【静态确认】

- 位置：[entity-recognition.service.ts](D:/MediBrain-Hospital/apps/server/src/entity/entity-recognition.service.ts:58)、[graph-manage.service.ts](D:/MediBrain-Hospital/apps/server/src/graph/graph-manage.service.ts:85)、[index-graph.js](D:/MediBrain-Hospital/scripts/embedding/index-graph.js:181)。
- 内存词典只在启动时加载，没有图谱写入后的刷新调用或刷新接口。多个后端副本会分别保留旧词典。
- 向量索引由离线脚本维护；脚本会跳过已经存在的实体名，而非更新其描述向量，也没有对应删除流程。
- 影响：新增、重命名或删除实体后，问答识别与向量候选可能继续使用旧数据。
- 修复：图谱提交成功后发布变更事件，更新词典与向量索引，并支持全量重建及多副本一致性检查。

### 16. P2：读取了病因等属性，却没有返回或送入问答【静态确认】

- 位置：[graph.service.ts](D:/MediBrain-Hospital/apps/server/src/neo4j/graph.service.ts:85)、[qa.service.ts](D:/MediBrain-Hospital/apps/server/src/qa/qa.service.ts:163)。

- 影响：图谱已存储的病因、预防等内容仍可能无法成为回答依据。
- 修复：将属性纳入明确的疾病详情结构，并让意图和事实组装覆盖对应属性。

### 17. P2：模型请求等待可能超过前端和代理的等待上限【静态确认】

- 位置：[openai-compatible.provider.ts](D:/MediBrain-Hospital/apps/server/src/llm/providers/openai-compatible.provider.ts:36)、[ollama.provider.ts](D:/MediBrain-Hospital/apps/server/src/llm/providers/ollama.provider.ts:31)。

- 影响：客户端已经失败，后端还可能继续等待模型，现有降级出现得太晚。
- 修复：为整个问答请求设定小于客户端期限的时间预算，并在各阶段配置取消和超时。
